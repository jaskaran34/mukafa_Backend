Mukafa API

API for managing partners, staff, members, transactions, and reward cards.

Partner: A partner represents a business or organization that can register and manage members in the Mukafa system. To begin, a partner must first register with Mukafa by submitting their details. Upon successful registration and after approval from the Mukafa team, the partner will gain API access. This process includes whitelisting the partner's IP address to ensure secure communication with the Mukafa system. Once the partner is approved, they will receive login credentials that allow them to authenticate using email and password to obtain an API token. This token must be included in the Authorization header as a Bearer token in subsequent requests.

Card: Cards represent a tiered rewards system associated with a partner. These cards define the rules and benefits, such as how many Mukafa points a user earns based on specific actions, such as spending money on the partner's website. For example, a user may be assigned a Tier 1 card, where for every 100 units spent, they earn 100 Mukafa points. Depending on the card tier, the reward may vary, with some tiers offering more points or additional benefits (e.g., Tier 2 may offer 150 points for the same amount spent).

Additionally, based on the member's activity and performance, they may be promoted to a higher tier. For instance, if a user spends more or meets certain performance metrics defined by the partner, they can move from Tier 1 to Tier 2, which would provide them with greater rewards, such as earning more Mukafa points per transaction.

Member: A member is an individual registered under a partner who participates in the Mukafa program. Members can receive a Mukafa number, participate in the program, and track their balance and points. Each member has unique information like their phone number, birthday, and balance.

get /partner/otp/{message_id}/{id}/{request_type}
Send OTP (partnerOtpMessageIdIdRequestTypeGet)
Sends an OTP for the specified request type (cancel_tran, register_customer, issue, redeem).

Path parameters

message_id (required)
Path Parameter — A UUID v4 identifier for the OTP request. format: uuid
request_type (required)
Path Parameter — Type of OTP request. Must be one of <code>cancel_tran</code>, <code>register_customer</code>, <code>issue</code>, or <code>redeem</code>.
id (required)
Path Parameter — <ul> <li>If <code>request_type</code> is <code>cancel_tran</code>, this is the Transaction ID.</li> <li>If <code>request_type</code> is <code>register_customer</code>, this is the mobile number in the format <code>+XX-XXXXXXXXXX</code>.</li> <li>If <code>request_type</code> is <code>issue</code> or <code>redeem</code>, this is the Mukafa number.</li> </ul>

Return type

inline_response_200

Example data

Content-Type: application/json
{
  "message" : "OTP sent"
}
